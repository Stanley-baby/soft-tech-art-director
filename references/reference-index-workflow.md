# Reference Index Workflow

Use this workflow when the user supplies a folder, ZIP, spreadsheet, screenshot set, or wants a persistent reference library.

## Purpose

Turn inspiration images into auditable design evidence. A reference is never an all-purpose style command. Record what to borrow, what not to inherit, and the specific design role it serves.

## Intake

1. Preserve original files and filenames.
2. Ignore system metadata such as `.DS_Store`, `__MACOSX`, and thumbnails.
3. Treat folder names as provisional Primary Family labels.
4. Count valid image files and report the actual number.
5. Create contact sheets by folder when visual inspection is practical.

## Required columns

Create one row per image with:

- Reference ID
- File
- Folder
- Primary Family
- Secondary Family
- Reference Role
- Layout
- Color
- Typography
- Material
- Data & Motion
- Visual Ingredients
- Preference: Unmarked, Like, Maybe, Reject
- Avoid
- Source
- Notes
- Review Status: To Review, Confirmed, Move, Split

Use bilingual labels when the user's working language is Chinese.

## Classification rules

- Assign exactly one Primary Family.
- Assign at most one Secondary Family; leave blank when unnecessary.
- Assign one dominant Reference Role: Layout, Color, Typography, Material, Data, Interaction, or Photography.
- Select three to five ingredients that can actually be observed.
- Do not infer Source when no product name or URL is available.
- Keep `Preference`, `Avoid`, and `Source` editable rather than inventing user opinions.
- Mark ambiguous images as boundary cases in Notes instead of forcing a clean classification.

## How the Skill uses the index

During Style Exploration:

1. Filter references by product-relevant Primary Family.
2. Select examples with different Reference Roles; do not show five near-identical material references.
3. Explain which rule each image contributes.
4. Avoid recommending a family solely because it has more images.

During Reference Feedback:

1. Ask for Like, Maybe, or Reject.
2. Ask what specifically caused the reaction only when unclear.
3. Translate feedback into Stable Preference, Contextual Preference, Rejected Pattern, or Open Question.
4. Update `Avoid`, Notes, and Review Status.

During Style Lock:

1. Use confirmed references only.
2. Build `Borrow / Preserve / Avoid` rules from individual Reference Roles.
3. Include the stable Reference IDs in the Style Profile.
4. Never copy logos, proprietary compositions, or brand-specific identity.

After route selection and reference confirmation, assemble a case-specific reference set using [case-board-workflow.md](case-board-workflow.md). The index is the retrieval layer; the Case Board is a human decision record, never the generation constraint. Preserve atomic reference images separately for Style Proof generation.

## Privacy and sharing hygiene

- Treat user-provided references as private working material unless the user explicitly asks to publish them.
- Do not expose local paths, upload IDs, account names, email addresses, phone numbers, avatars, or unrelated personal text in a Reference Index, Case Board, Style Proof, or exported package.
- Use neutral Reference IDs in visible outputs. Preserve original filenames internally only when they contain no personal information.
- Before public sharing or sale, flag recognizable third-party people, photography, product screenshots, logos, and brand identity as potential permission or licensing risks.
- Do not claim that a third-party reference is licensed merely because it is publicly visible online.

## Taxonomy growth rule

Do not create a new Style Family for every visual combination. Prefer an Ingredient or substyle when the difference is mostly material, color, or lighting. Promote a direction to a core family only when:

- at least five coherent references exist;
- it has a distinct product metaphor;
- a non-designer can distinguish it from neighboring families;
- it can guide both a visual keyframe and an implementable interface.

Examples:

- `Shadow Gradient` is an Ingredient.
- `Dark Signal Intelligence` is a substyle or family because it combines a distinct monitoring metaphor with data, light, and spatial behavior.
- `Quiet Gradient Intelligence` is a specific reusable direction because calm typography and atmospheric color fields consistently express background computation.
